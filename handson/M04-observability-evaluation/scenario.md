# モジュール 4: 本番環境のモニタリング、オブザーバビリティ、評価 - ハンズオンシナリオ

## シナリオ概要

あなたは SaaS プラットフォームの SRE（Site Reliability Engineer）です。本番環境で稼働中のマルチエージェントカスタマーサポートシステムの品質とパフォーマンスを可視化し、問題の早期発見と継続的改善を実現する必要があります。

OpenTelemetry ベースの分散トレーシング、CloudWatch ダッシュボード、AgentCore Evaluations を活用して、包括的なオブザーバビリティと評価フレームワークを構築します。

## 学習目標

このハンズオンを完了すると、以下ができるようになります：

1. **分散トレーシング**: OpenTelemetry を使用してエージェントの実行をトレース・スパン単位で可視化する
2. **CloudWatch 統合**: エージェント固有のメトリクスとダッシュボードを構築する
3. **エージェント評価**: 組み込みエバリュエーターとカスタムエバリュエーターを使用した品質評価を実施する
4. **オブザーバビリティ設計**: トレースレベルとスパンレベルのメトリクスの違いを理解する

## トレースレベル vs スパンレベルのメトリクス

| レベル | 計測対象 | 例 |
|-------|---------|---|
| トレースレベル | エージェント実行全体 | 全体レイテンシー、総トークン数、成功/失敗 |
| スパンレベル | 個々のステップ | LLM 呼び出し時間、ツール実行時間、各ステップのトークン数 |

## エージェント評価の 3 ステージ

| ステージ | 目的 | 手法 |
|---------|------|------|
| 計測 (Measure) | メトリクスの収集 | 組み込み + カスタムエバリュエーター |
| 判断 (Judge) | 品質のスコアリング | LLM as a Judge、Programmatic |
| インサイト (Insight) | 改善点の特定 | トレンド分析、根本原因調査 |

## 使用する AWS サービス

- Amazon Bedrock AgentCore Observability
- Amazon Bedrock AgentCore Evaluations
- Amazon CloudWatch（メトリクス・ダッシュボード・アラーム）
- OpenTelemetry SDK
- Strands Agents SDK
