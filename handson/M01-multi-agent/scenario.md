# モジュール 1: マルチエージェントアーキテクチャと通信パターン - ハンズオンシナリオ

## シナリオ概要

あなたは大手 EC サイトのプラットフォームエンジニアです。カスタマーサポート部門から「問い合わせの種類（技術サポート・請求・商品レコメンデーション）ごとに専門性の高い対応をしたい」という要望を受けました。単一のエージェントでは認知負荷やコンテキスト枯渇の問題が発生するため、マルチエージェントアーキテクチャを採用してシステムを構築します。

Strands Agents SDK を使用して、以下の 3 つのオーケストレーションパターンを実装し、それぞれの特性を理解します。

## 学習目標

このハンズオンを完了すると、以下ができるようになります：

1. **マルチエージェントの必要性を理解する**: シングルエージェントの制限（認知負荷・コンテキスト枯渇・ドメイン専門化）を体感する
2. **Workflow パターン**: 事前定義された順序で専門エージェントが連携するパイプラインを構築する
3. **Graph パターン**: 条件分岐を含む構造化されたフローチャート型のオーケストレーションを実装する
4. **Swarm パターン**: エージェントが自律的にハンドオフする動的コラボレーションを実装する
5. **メモリ共有**: AgentCore Memory を使用したエージェント間のステート共有を実装する
6. **MCP 統合**: ツールとしてのエージェントパターンを MCP サーバー経由で実装する

### 通信パターン比較

| パターン | 特徴 | ユースケース |
|---------|------|-------------|
| Workflow | 順次実行、事前定義 DAG | 反復可能な複雑な操作 |
| Graph | 条件分岐、構造化フロー | ブランチロジックが必要なプロセス |
| Swarm | 自律ハンドオフ、動的 | 多様な専門的視点が必要な問題 |

## 使用する AWS サービス

- Amazon Bedrock（Converse API / Claude Sonnet・Nova）
- Amazon Bedrock AgentCore Memory
- Strands Agents SDK（Workflow / Graph / Swarm）
- MCP（Model Context Protocol）

## 所要時間

約 60 分

## 前提条件

- AWS CLI 設定済み
- Python 3.12+（EC2 環境では venv 自動有効化）
- 以下の Python パッケージがインストール済み：
  - `strands-agents`
  - `strands-agents-tools`
  - `bedrock-agentcore`
- Amazon Bedrock で以下のモデルアクセスが有効化済み：
  - Anthropic Claude Sonnet 4.6
  - Amazon Nova Lite / Pro
