# モジュール 2: コンテキストエンジニアリングとパフォーマンスの最適化 - ハンズオンシナリオ

## シナリオ概要

あなたは SaaS プラットフォームの AI エンジニアです。顧客対応チャットボットが長時間の会話でパフォーマンスが低下し、コストが増大する問題を抱えています。1 会話あたり 20〜30 回のやり取りが発生し、コンテキストウィンドウの枯渇やトークンコストの増大が課題になっています。

コンテキストエンジニアリングの各種戦略を実装し、パフォーマンスとコストを最適化します。

## 学習目標

このハンズオンを完了すると、以下ができるようになります：

1. **コンテキストの重要性を理解する**: 有限リソースとしてのコンテキストウィンドウとその障害モードを理解する
2. **入力形式の最適化**: TOON（トークン指向オブジェクト記法）などの手法でトークン使用量を削減する
3. **プロンプトキャッシュ**: Bedrock のプロンプトキャッシュ機能を活用してコストとレイテンシーを削減する
4. **コンテキスト圧縮**: SummarizingConversationManager を使用した会話要約を実装する
5. **コンテキスト分離**: マルチエージェントによるコンテキスト境界の分割を実装する

## コンテキストの障害モード

| 障害モード | 説明 | 影響 |
|-----------|------|------|
| ポイズニング | 不完全な情報から誤った前提を構築 | 誤った回答 |
| ディストラクション | コンテキストが多すぎて集中できない | 品質低下 |
| 混同 | 無関係なコンテキストで不適切なツール呼び出し | 意図しない動作 |
| クラッシュ | 矛盾した指示で意思決定が停止 | 応答不能 |

## 使用する AWS サービス

- Amazon Bedrock（Converse API / プロンプトキャッシュ）
- Amazon Bedrock AgentCore Memory
- Strands Agents SDK（SummarizingConversationManager）

## 所要時間

約 45 分

## 前提条件

- AWS CLI 設定済み
- Python 3.12+（EC2 環境では venv 自動有効化）
- 以下の Python パッケージがインストール済み：
  - `strands-agents`
  - `bedrock-agentcore`
  - `boto3`
- Amazon Bedrock で以下のモデルアクセスが有効化済み：
  - Anthropic Claude Sonnet 4（プロンプトキャッシュ対応）
  - Amazon Nova Pro / Lite
